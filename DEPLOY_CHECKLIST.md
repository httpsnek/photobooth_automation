# InstaBOX — чек-лист запуску точки

Проходити зверху вниз. `[ ]` — не перевірено, `[x]` — готово й перевірено.
Детальні кроки «як саме» — у **DEPLOY.md**. Тут — **що має бути зроблено й що перевірити**.

Значення в кутових дужках беруться з `.env` цієї точки.

---

## 0. Передумови

- [ ] ПК будки на Windows 10/11, камера + термопринтер працюють у самому dslrBooth
- [ ] Сенсорний монітор (HDMI + USB) під'єднаний до ноутбука будки
- [ ] Власний роутер (4G або звичайний), **не гостьовий Wi-Fi ТЦ** — потрібен лише для оплати
- [ ] Готовий `.env` для цієї точки (на флешці)
- [ ] Власник натиснув **Start** у бота `t.me/InstaBOX_control_bot`
- [ ] Активна підписка dslrBooth (або триал — лише для першого тесту, з водяним знаком)

## 1. Конфігурація `.env`

Скопіювати готовий `.env` у корінь проєкту. Перевірити ключі:

### Ідентифікація точки
- [ ] `BOOTH_ID` — унікальний (напр. `kiosk_mall_01`), лише `a-z 0-9 - _`
- [ ] `BOOTH_NAME` — назва/локація (видно у виписці банку та в кожному сповіщенні)
- [ ] `SUPPORT_TELEGRAM` — @юзернейм / t.me-посилання підтримки (на екрані помилки — QR, гість сканує телефоном). `SUPPORT_PHONE` — якщо є телефон, текстом

### Оплата
- [ ] `PAYMENT_PROVIDER=monobank`
- [ ] `BANK_TOKEN` — бойовий X-Token еквайрингу *(саме `BANK_TOKEN`, не `MONO_TOKEN`)*
- [ ] `PRICE_UAH` — актуальна ціна
- [ ] `INVOICE_TTL_SEC=180` — час життя рахунку
- [ ] `check.bat` → рядок `acquirer` = `[  OK ] ... <merchantName>`

### Прив'язка до заліза
- [ ] `PRINTER_NAME` — точна системна назва принтера (як у «Пристрої та принтери»); порожньо = принтер за замовчуванням
- [ ] `PRINTER_CHECK_ENABLED=1` — перевірка черги друку Windows
- [ ] `DSLRBOOTH_HOTKEY` — та сама клавіша, що призначена триггером у dslrBooth

### Сповіщення
- [ ] `TELEGRAM_ALERTS_BOT_TOKEN` — валідний
- [ ] `TELEGRAM_ADMIN_CHAT_ID` — chat_id власника
- [ ] Тестове повідомлення доходить: `check.bat` → `telegram [  OK ]`, і після старту в чат приходить `▶️ Запуск`

### Прапорці (обов'язково на бойовій точці)
- [ ] `FAKE_TRIGGER_OK=0`
- [ ] `MOCK_FAIL=0`

## 2. Windows

### setup.bat робить автоматично (запустити «Від імені адміністратора»)
- [ ] `.venv` + залежності (`pyautogui`, `psutil` тощо)
- [ ] Дві задачі планувальника: **`InstaBOX-<BOOTH_ID>`** та **`InstaBOX-watchdog-<BOOTH_ID>`**
      (тригер *AtLogOn*, *Run with highest privileges*, авто-рестарт)
- [ ] Правило брандмауера: вхідний **TCP 8000** дозволено для локальної мережі
- [ ] Вимкнено: сон / гібернація / вимкнення монітора / **USB Selective Suspend**

### Вручну (setup.bat НЕ робить)
- [ ] **Автоматичний вхід** у Windows (`netplwiz` → зняти «Вимагати введення імені та пароля»).
      **Без цього автозапуск (`-AtLogOn`) не спрацює.**
- [ ] Windows Update → «години активності» на цілу добу / відкласти перезавантаження
- [ ] BIOS: **Restore on AC Power Loss = On** (якщо немає ДБЖ)
- [ ] Бажано невеликий **ДБЖ** на ПК + роутер
- [ ] Статичний IP (DHCP-резервація) для ПК на роутері

### Перевірка
- [ ] `check.bat` → усе `[  OK ]` або усвідомлений `[ WARN ]`, **жодного `[ FAIL ]`**
- [ ] `schtasks /Query /TN InstaBOX-<BOOTH_ID>` — задача є
- [ ] `schtasks /Query /TN InstaBOX-watchdog-<BOOTH_ID>` — задача є

## 3. dslrBooth + камера

- [ ] Ярлик `dslrBooth.exe` у `shell:startup` (автозапуск)
- [ ] Вхід в акаунт з активною підпискою
- [ ] Сесія **Print** на 4 кадри
- [ ] **Вимкнено всі екрани шерінгу** (email / SMS / QR-share) — інакше dslrBooth зависне на них і наступна сесія не стартує
- [ ] Автодрук: після 4 кадрів макет іде на принтер **без підтвердження**
- [ ] Повноекранний режим без панелей Windows; кнопку «Почати зйомку» на екрані прибрано (запуск лише за нашим сигналом)
- [ ] **«Always on top» ВИМКНЕНО** — інакше наш QR ніколи не накриє вікно dslrBooth

### Гість бачить себе і може перезняти (правки клієнта)
- [ ] *Settings → Screen Editor → Capture Screen* → **Show Live View** увімкнено
- [ ] *Settings → Capture Settings → Photo*: «Time Before First / Other Photos» **> 3 с**
      (інакше live view не встигає з'явитися)
- [ ] Перегляд кожного кадру з кнопкою **Retake** увімкнено, час ~**5 с**
      *(це НЕ екран шерінгу — той лишається вимкненим)*
- [ ] Кнопка Retake реально натискається пальцем на моніторі
- [ ] Перезнятий кадр не ламає лічильник: у логу немає стрибка номера кадру

### Режим подій (обов'язково — підписка є)
- [ ] У `.env`: `DSLRBOOTH_TRIGGER=rest`, `DSLRBOOTH_EVENTS_ENABLED=1`, `DSLRBOOTH_API_PASSWORD=<пароль REST з dslrBooth>`
- [ ] dslrBooth → *Settings → General → Triggers* → URL:
      **`http://127.0.0.1:8000/dslrbooth/event?token=<DSLRBOOTH_EVENT_TOKEN>`**
      *(саме `/dslrbooth/event`, не `/api/dslr-event`)*
- [ ] Тестова сесія → у `logs/<BOOTH_ID>.log` немає рядків `unmapped booth event`
      (якщо є — звірити назви подій із таблицею `_MAP` у `backend/booth_events.py`)

### Камера (фізика)
- [ ] Постійне живлення 220V (пустушка замість акумулятора)
- [ ] Ручний режим: фокус / експозиція / баланс білого зафіксовані

## 4. Сенсорний монітор (HDMI + USB)

Один екран на всю будку. Його по черзі займають два повноекранні вікна:
**Chrome** (наш кіоск) — увесь час, крім зйомки; **dslrBooth** — на час зйомки,
щоб гість бачив себе, відлік і кнопку Retake. Перемикає бекенд.

- [ ] Монітор під'єднано: **HDMI** (зображення) + **USB** (сенсор)
- [ ] Кришку ноутбука закрито; Електроживлення → «при закритті кришки — **нічого не робити**»
- [ ] Windows працює на моніторі як на **єдиному** дисплеї (не «розширити»)
- [ ] Сенсор влучає в ціль: «Параметри планшетного ПК» → *Налаштувати* → прив'язати дигитайзер до цього екрана
- [ ] `start_kiosk.bat` в автозавантаженні (`shell:startup` — ярлик кладе `setup.ps1`),
      і саме **того користувача**, під яким автоматично заходить будка
- [ ] Chrome відкривається сам у режимі кіоску, без адресного рядка й панелей
- [ ] `check.bat` → рядки `screen`, `screen · dslrBooth`, `screen · kiosk` — усі знайдені
- [ ] Перевірено вигляд екранів: завантаження · активний QR · друк · «Готово» · екран помилки

### Перемикання вікон (перевірити руками)
- [ ] Оплата → вікно **dslrBooth саме виринає** поверх Chrome
- [ ] Після друку → **Chrome повертається** сам: «Друкуємо» → «Готово»
- [ ] Помилка / повернення коштів → Chrome теж повертається (гість має бачити причину, а не dslrBooth)

## 5. Натурні тести (перед здачею)

Спершу `PRICE_UAH=1`, `PAYMENT_PROVIDER=monobank`, перезапустити задачу.
Після тестів повернути `PRICE_UAH=<реальна>`.

| # | Сценарій | Очікувана реакція | ✔ |
|---|---|---|---|
| 1 | **Штатний платіж (1 грн)** | скан QR → оплата → Telegram `💰 +1 UAH` → **вікно dslrBooth виринає**: live view, відлік, 4 кадри, Retake за потреби → друк смужки → **Chrome повертається**: «Друкуємо» → «Готово» → скид у IDLE → новий QR | [ ] |
| 2 | **Ігнорування QR (таймаут)** | QR висить 180 с → фінальна звірка статусу інвойсу → безпечний скид сесії → новий QR *(якщо оплата прийшла в останню мить — сесія стартує; якщо пізніше — інвойс у черзі, гроші повертаються самі)* | [ ] |
| 3 | **Вимкнений dslrBooth** | закрити dslrBooth → `_preflight()` не створює QR → екран `Тимчасово не працює` + Telegram `🛑 Фотобудка (dslrBooth) не відповідає` → запустити dslrBooth → кабінка сама повертається до роботи | [ ] |
| 4 | **Немає паперу / принтер offline** | вимкнути принтер (або дійсно закінчився папір) → статус черги Windows / лічильник = 0 → `_preflight()` блокує видачу QR → `Тимчасово не працює` + Telegram. Після заміни рулону: `http://<IP>:8000/admin/paper-reset?token=<ADMIN_TOKEN>` | [ ] |
| 5 | **Аварія під час зйомки (hard reset)** | знеструмити ПК під час спалахів → увімкнути → при старті `_reconcile_on_start()` знаходить незавершену сесію → Monobank скасовує платіж → Telegram `♻️` + запис у лог. *(Якщо інтернету ще нема — повернення стає в чергу і добивається саме)* → **перевірити, що гроші повернулись на картку** | [ ] |
| 6 | **Зависання бекенду (Watchdog)** | «заморозити» процес → watchdog не отримує `200 OK` від `/health` 2 рази поспіль (або той самий стан не змінюється > `WATCHDOG_STUCK_SEC`) → примусовий `taskkill` → `run.bat` піднімає заново (~5–10 с) → Telegram `🐕 Перезапуск бекенду` | [ ] |
| 7 | **Подвійна оплата одного QR** | двоє сканують той самий QR → перший оплатив → інвойс уже `success` → другий бачить «рахунок вже оплачено», кошти **не списуються** | [ ] |
| 8 | **Короткочасна втрата інтернету під час опитування оплати** | вимкнути Wi-Fi на 10–20 с під час очікування → бекенд не падає, продовжує опитування → після відновлення бачить реальний статус | [ ] |

### Фінальна перевірка «все піднімається саме»
- [ ] Витягнути живлення ПК на 10 с → увімкнути
- [ ] Windows зайшов сам → `run.bat` піднявся → dslrBooth запустився → Chrome відкрив кіоск на моніторі
- [ ] `check.bat` — знову все зелене
- [ ] Залишити на 10–15 хв, зробити 2–3 реальні зйомки; перевірити Telegram (оплати; вечірня зведення о `DAILY_SUMMARY_HOUR`)

## Швидка діагностика

| Симптом | Дивитись |
|---|---|
| Екран: `Тимчасово не працює` | причина — у Telegram; лог `logs/<BOOTH_ID>.log` |
| Немає сповіщень у Telegram | власник не натиснув Start; або невірний `TELEGRAM_ADMIN_CHAT_ID` |
| `check.bat` → `acquirer [ FAIL ]` | невірний `BANK_TOKEN` або немає інтернету |
| Камера не знімає після оплати | `DSLRBOOTH_HOTKEY` ≠ клавіша в dslrBooth; dslrBooth не у фокусі; або процес не запущено |
| Кіоск не відкрився | `start_kiosk.bat` не в автозавантаженні потрібного користувача; бекенд не піднявся |
| Вікно dslrBooth не виринає | `WINDOW_SWITCH_ENABLED=0`; у dslrBooth увімкнено «always on top»; `check.bat` → `screen · dslrBooth` |
| Chrome не повертається після зйомки | не прийшла подія `printing`/`session_end` — звірити Triggers URL; `check.bat` → `screen · kiosk` |
| Черга повернень росте | `http://<IP>:8000/status` → рядок «Черга повернень»; лог |
| Логи | `logs/<BOOTH_ID>.log`, `logs/watchdog.log` |
